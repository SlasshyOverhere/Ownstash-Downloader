## 2024-05-24 - Arbitrary Code Execution Vulnerability via Custom Player Path
**Vulnerability:** In `src-tauri/src/commands.rs`, the `open_with_external_player` command accepts a user-provided `player_path` string from the frontend. This path is used directly as the executable in `std::process::Command::new(&player)`. An attacker who can control the frontend arguments (e.g., via a malicious extension or XSS) can supply an arbitrary executable path (like `cmd.exe` or `/bin/sh`) along with a controlled argument, leading to Arbitrary Code Execution (ACE).
**Learning:** Even though the function checks if the `player` path exists using `std::path::Path::new(&player).exists()`, this does not prevent an attacker from supplying the absolute path to a system shell (e.g., `C:\Windows\System32\cmd.exe` or `/bin/bash`). If `Command::new` receives a system shell, the provided `file_path` might be interpreted as a command script. Relying on frontend-provided paths for executables is inherently insecure.
**Prevention:** Executable paths must not be provided directly from the frontend. Instead, the backend should retrieve the custom player path securely from the application's configuration state (e.g., SQLite settings or encrypted vault config). Alternatively, if the frontend must provide the path, use Tauri's scoped shell plugin (`shell-plugin`) to strictly control allowed executables and arguments, or enforce strict allowlisting and validation of the executable.
