## 2024-05-18 - Prevent Command Injection / Arbitrary Execution via External Player Path
**Vulnerability:** The application allowed the frontend to provide an arbitrary path to an external media player executable (`player_path`), which was then directly executed by the backend using `std::process::Command::new()`. This could allow an attacker who controls or compromises the frontend to execute arbitrary commands on the system.
**Learning:** External executable paths should never be blindly trusted from the frontend because it bypasses the system's security controls, resulting in an Arbitrary Code Execution (ACE) vulnerability. Path validation is insufficient against a compromised frontend passing paths like `cmd.exe` or `/bin/sh`.
**Prevention:** Instead of accepting paths from the frontend, retrieve executable paths from secure server-side or database-managed settings (e.g., `get_setting("external_player_path")`), ensuring only trusted, system-configured executables are spawned.
