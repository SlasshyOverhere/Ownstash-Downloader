## 2025-01-20 - Prevent Accidental Data Loss with Browser Confirm Dialogs
**Learning:** Destructive bulk actions, like clearing all downloads or search history, previously occurred immediately upon button click. While fast, this lack of friction increases the risk of accidental data loss, which can be frustrating for users.
**Action:** Always wrap destructive bulk action handlers (e.g., `handleClearAll`) in a native `window.confirm()` dialog. Since this is a simple UX tweak requiring a confirmation dialog, use the native browser `window.confirm` instead of `@tauri-apps/plugin-dialog` to avoid heavy plugin overhead and backend Rust initialization dependencies, keeping changes under 50 lines.

## 2025-01-20 - Keyboard Accessibility for Hover-Revealed Actions
**Learning:** Action buttons in list cards (like DownloadCard and HistoryCard) were revealed using `group-hover:opacity-100`. This made them entirely invisible and potentially inaccessible to keyboard-only users navigating via the `Tab` key, as focusing an inner button wouldn't trigger the hover state on the parent container.
**Action:** When using `opacity-0 group-hover:opacity-100` to hide and reveal elements based on mouse interaction, always pair it with `focus-within:opacity-100` on the container. This ensures that when a keyboard user tabs into any element within that container, the entire action group becomes visible. Additionally, ensure all interactive elements receive robust focus indicators like `focus-visible:ring-2 focus-visible:ring-primary focus-visible:ring-offset-2 focus-visible:ring-offset-background`.
